# S0.5 — Handy on Windows, Pumice in WSL

Scope: confirm that Handy installed on Windows can reach a Pumice listener running inside WSL and bound to `127.0.0.1`, with nothing installed on Windows. Record the WSL networking mode and any setting the owner has to change. Tested on 2026-10-03 and 2026-10-04.

## Environment

- **Windows:** Windows 11, build 10.0.26200.
- **WSL:** version 2.7.14.0. `wslinfo --networking-mode` reports `nat`.
- **`.wslconfig`:** has no networking keys (`networkingMode`, `localhostForwarding`), so the WSL defaults apply. With NAT, `localhostForwarding` is on by default. Only `[wsl2] memory/processors/vmIdleTimeout`, `[general] instanceIdleTimeout` and `[experimental] autoMemoryReclaim` are set.
- **Listener:** `pumice listen --port 18080` from the S0.4 prototype. It binds `127.0.0.1:18080` inside WSL (`ss -ltn` shows `127.0.0.1:18080`).

## Tests

The Windows-side checks used the Windows PowerShell that ships with Windows, called through WSL interop at `/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe`. Nothing was installed on Windows.

| From Windows | Result |
| --- | --- |
| `GET http://localhost:18080/v1/models` | 200, correct JSON |
| `POST http://127.0.0.1:18080/v1/chat/completions` | 200, echo completion |
| `GET http://[::1]:18080/v1/models` | **Fails** ("Unable to connect to the remote server") |
| 5 × `localhost` | 2090, 15, 14, 14, 14 ms |
| 5 × `127.0.0.1` | 14, 14, 14, 14, 14 ms |
| **Handy (Custom provider, base URL `http://127.0.0.1:18080/v1`)** | `GET /v1/models` and `POST /v1/chat/completions` both arrived, and the response was pasted. See S0.1. |

On the WSL side the listener logged the remote address of every Windows request as `127.0.0.1:<port>`. WSL's localhost forwarding delivers them as loopback connections, so binding to `127.0.0.1` only is enough. There's no need to bind `0.0.0.0` or open a firewall port.

## Findings

- **It works out of the box in NAT mode.** Handy on Windows reaches a Pumice listener bound to `127.0.0.1` inside WSL. The owner didn't change any setting. Combined with S0.1, this is the first working day-to-day setup for the MVP, as the spec expects.
- **Use `127.0.0.1` in Handy, not `localhost`.** Only IPv4 is forwarded: `[::1]` fails. Windows tries `::1` first for `localhost`, so the first request took ~2.1 s before falling back to IPv4; later requests were fast, probably because of a cached result. With `127.0.0.1` every request took ~14 ms. A 2 s hit on a dictation adds directly to the 30 s budget.
- **Pumice can stay bound to `127.0.0.1` only**, as AGENTS.md requires. Forwarded requests arrive as loopback.
- **WSL must be running.** NAT-mode forwarding only exists while the WSL VM is up. The owner's `.wslconfig` sets `vmIdleTimeout=-1` and `instanceIdleTimeout=-1`, which keep it up, but after a Windows restart Pumice has to be started again inside WSL. That happened during this test: the listener needed a manual restart after an accidental reboot.

## Questions for the owner

1. **The spec says `localhost`; the finding says `127.0.0.1`.** S0.5 reads: "Confirm that Handy on Windows reaches Pumice in WSL via `localhost`". `localhost` works, but the first request can take ~2 s because of the IPv6 attempt. Should the install guide (S7.3) tell users to put `http://127.0.0.1:<port>/v1` in Handy? Alternatively, Pumice could also listen on `[::1]` inside WSL, but that doesn't help, because NAT mode doesn't forward IPv6.
2. **Starting Pumice when Windows starts.** With Pumice in WSL, something has to start it after a reboot: a systemd user service in WSL, plus something that starts WSL itself (Windows Task Scheduler running `wsl.exe` at login). The second part touches Windows. Is a documented Task Scheduler entry acceptable for the day-to-day setup, or should this wait for the native Windows build?
3. **Mirrored networking mode** (`networkingMode=mirrored`) was not tested, since the owner uses NAT. It might forward IPv6 loopback too. Should it be tested, or just documented as an alternative?

## Owner decisions (2026-10-04)

- **`127.0.0.1` vs `localhost`:** not a problem for now. Use `http://127.0.0.1:<port>/v1` in Handy in the meantime.
- **Starting at boot:** deferred. In the future Pumice is expected to run as its own Windows service, so the WSL autostart setup is not pursued.
