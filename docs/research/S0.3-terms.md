# S0.3 — Terms of use

Scope: assess Pumice’s proposed personal use: a local program spawning an official CLI non-interactively to format its owner’s dictation, without tools, in a fresh empty temporary directory, without reading or reusing credentials. Sources were accessed through live web research on **2026-10-03**. No files were modified and no AI CLI was run. Ratings apply to this integration, not merely to whether a CLI supports headless execution.

**This is a summary for the owner, not legal advice.**

## Anthropic — Claude Code with Pro/Max

### Sources

All accessed **2026-10-03**:

- [Usage Policy](https://www.anthropic.com/legal/aup), displayed effective September 15, 2025.

- [Run Claude Code programmatically](https://code.claude.com/docs/en/headless).
- [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview).
- [Use the Claude Agent SDK with your Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), dated June 16, 2026.
- [Claude Code with Pro/Max](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan), [Pro limits](https://support.claude.com/en/articles/8325606-what-is-the-pro-plan), [Max limits](https://support.claude.com/en/articles/11049741-what-is-the-max-plan).

### Rule summary

Consumer Terms §3(7) prohibit automated or non-human access except through an Anthropic API key or where Anthropic explicitly permits it. The Usage Policy also applies to submitted dictation; treating text as data does not exempt its content from that policy. [Consumer Terms](https://www.anthropic.com/legal/consumer-terms), [Usage Policy](https://www.anthropic.com/legal/aup)

Anthropic explicitly documents `claude -p` for scripts, pipelines and CI/CD. Its subscription help page acknowledges that `claude -p` and Agent SDK usage consume subscription limits. This supports personal headless use through the official CLI. [Programmatic-use docs](https://code.claude.com/docs/en/headless), [Subscription SDK notice](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)

However, legal documentation directs developers building products or services to API-key authentication and prohibits routing requests through consumer credentials on behalf of users. The SDK overview requires prior approval for third-party products offering Claude subscription rate limits. Whether a distributed local wrapper that only spawns the already-authenticated official CLI falls within that restriction is **unconfirmed**. [Legal docs](https://code.claude.com/docs/en/legal-and-compliance), [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)

The current restriction is confirmed; an exact January/February 2026 introduction date was **unconfirmed** from the primary sources reviewed. The Consumer Terms’ displayed effective date alone does not establish when the separate documentation changed. [Consumer Terms](https://www.anthropic.com/legal/consumer-terms), [Legal docs](https://code.claude.com/docs/en/legal-and-compliance)

### Quota/rate limits

**The reported June 2026 split was announced and then paused.** The official help article’s June 15 update says `claude -p`, Agent SDK and third-party app usage still consume subscription limits. Its preserved description of separate monthly credits is explicitly no longer taking effect; those credits are unavailable. A currently active separate headless quota is therefore refuted by the retrieved notice. [Official pause notice](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)

Claude and Claude Code share subscription limits. Pro and Max have five-hour session limits and weekly limits; Max offers 5× or 20× Pro’s per-session allowance. Capacity depends on context, model and task, so there is no confirmed fixed “dictations per day” allowance. Additional usage credits/API billing are optional paid routes. [Shared limits and billing](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan), [Pro](https://support.claude.com/en/articles/8325606-what-is-the-pro-plan), [Max](https://support.claude.com/en/articles/11049741-what-is-the-max-plan)

### Rating: unclear

Personal headless execution has supporting documentation. Permission to distribute Pumice as a subscription-backed product remains **unconfirmed** because the product-integration restrictions are broader than credential extraction alone. [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)

## OpenAI — Codex CLI with ChatGPT Plus/Pro

### Sources

All accessed **2026-10-03**:

- [Terms of Use outside the EEA, Switzerland and UK](https://openai.com/policies/row-terms-of-use/), relevant to a Brazilian resident.
- [European Terms](https://openai.com/policies/terms-of-use/), for residents covered by that version.
- [Service Terms, including Codex](https://openai.com/policies/service-terms/).
- [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode).
- [Authentication](https://learn.chatgpt.com/docs/auth).
- [Pricing and usage limits](https://learn.chatgpt.com/docs/pricing).

### Rule summary

OpenAI documents `codex exec` for scripts, pipelines and output consumed by other tools. The same page describes running automation with a Codex user account when ChatGPT/Codex limits are needed, while recommending API keys as the default for CI automation. CLI authentication explicitly supports ChatGPT subscription access. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [Authentication](https://learn.chatgpt.com/docs/auth)

General consumer terms prohibit programmatic extraction of data/output, account sharing and bypassing rate limits. They also require compliance with product documentation. **Interpretation:** the expressly documented `codex exec` workflow supports Pumice’s ordinary personal CLI invocation; it is not blanket permission to scrape ChatGPT, redistribute account access or evade limits. No Pumice-specific contractual approval was found. [Terms](https://openai.com/policies/row-terms-of-use/), [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)

The documented account-authenticated CI workflow includes credential-handling steps outside Pumice’s rules. Pumice should use the owner’s existing official CLI login locally, without implementing credential migration or inspection. [Authentication](https://learn.chatgpt.com/docs/auth), [Repository credential rule](../../AGENTS.md)

### Quota/rate limits

Plus and Pro include Codex CLI access. Local and cloud work share plan allowances, with consumption varying by model, context, reasoning and tools. The retrieved pricing page estimates **15–160 GPT-6.1 Sol local messages per five hours on Plus**; these are estimates, not guaranteed message counts. It states that Pro currently has no five-hour limit, while weekly limits may apply. Extra credits and API-key usage are separately paid options. The usage dashboard supplies current account limits and reset times. [Pricing and limits](https://learn.chatgpt.com/docs/pricing)

### Rating: OK

This is the strongest documented subscription route for personal scripted use. “OK” means supported by the retrieved product documentation, subject to ordinary terms and limits; explicit approval of the exact dictation-wrapper product remains **unconfirmed**. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [Terms](https://openai.com/policies/row-terms-of-use/)

## Moonshot AI — Kimi Code CLI / Kimi For Coding

### Sources

All accessed **2026-10-03**:

- [Kimi Terms of Service](https://www.kimi.com/user/agreement/en/modelUse), displayed effective January 5, 2024.
- [Kimi Code Community Guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html).
- [Kimi command reference](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-command).
- [Membership benefits and limits](https://www.kimi.com/code/docs/en/kimi-code/membership.html).
- [Official OpenCode integration guide](https://www.kimi.com/code/docs/en/third-party-tools/opencode.html).

### Rule summary

The CLI documents `kimi -p` for non-interactive execution. Nevertheless, subscription guidelines state: “Don't use Kimi Code for non-interactive automation.” They restrict subscriptions to personal interactive use and identify scripted batch execution as outside normal use. Technical capability therefore does not establish subscription permission. [Command reference](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-command), [Guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html)

Kimi supports third-party clients, including OpenCode, and documents connecting with a subscription-associated Kimi For Coding API key. That client permission does not waive the interactive-use restriction. Pumice’s automated dictation calls should be treated as covered by the prohibition unless Moonshot confirms otherwise; an exception for one human-triggered dictation at a time is **unconfirmed**. [OpenCode guide](https://www.kimi.com/code/docs/en/third-party-tools/opencode.html), [Guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html)

### Quota/rate limits

Current membership documentation distinguishes plans:

- **New plans:** rolling five-hour limit and monthly total quota; no weekly quota.
- **Legacy plans:** five-hour limit, quota refreshing every seven days without rollover, and monthly total quota.
- Devices and API keys share the account allowance. New-plan Go has no coding quota; Plus and above include Kimi Code. Extra Usage can continue requests against a paid balance when enabled.

Exact fixed request/token allowances for Pumice are **unconfirmed**; inspect the account’s plan and quota display. [Membership documentation](https://www.kimi.com/code/docs/en/kimi-code/membership.html)

### Rating: risky

The proposed subscription use conflicts with an explicit non-interactive-use restriction. Using the official CLI or an approved alternative client does not resolve it. [Guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html)

### Rule summary

**Local tool: OK.** The MIT license permits using and modifying the software, and `opencode run` is explicitly documented for scripting and automation. OpenCode’s hosted-service Terms distinguish non-hosted open-source software, whose use is governed exclusively by its repository license. [License](https://github.com/anomalyco/opencode/blob/dev/LICENSE), [CLI docs](https://opencode.ai/docs/cli/), [Terms](https://opencode.ai/legal/terms-of-service)

**Upstream access requires separate permission:**

- **Claude Pro/Max: risky.** OpenCode itself says Anthropic prohibits subscription plugins and that bundled support was removed in version 1.3.0. Anthropic’s own authentication restrictions support that conclusion. [OpenCode provider docs](https://opencode.ai/docs/providers/), [Anthropic legal docs](https://code.claude.com/docs/en/legal-and-compliance)
- **Kimi For Coding: risky for Pumice.** Moonshot approves OpenCode as a client, but its subscription automation restriction still applies. [Kimi integration guide](https://www.kimi.com/code/docs/en/third-party-tools/opencode.html), [Guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html)
- **Other subscriptions: unconfirmed individually.** OpenCode advertises ChatGPT Plus support, but that statement is the tool vendor’s documentation, not independent provider authorization for every usage pattern. [Provider docs](https://opencode.ai/docs/providers/)

OpenCode’s hosted-service Terms also prohibit automated/programmatic extraction of output while its documentation provides API inference. Whether that clause permits normal scripted Zen inference needs clarification; the local software license does not answer it. [Hosted Terms](https://opencode.ai/legal/terms-of-service), [Zen docs](https://opencode.ai/docs/zen/)

### Quota/rate limits

The local CLI has no inference allowance of its own: quotas follow the configured upstream service. Kimi shares quota across clients. Zen uses separate per-token billing, lists some free models, and supports monthly spending limits; a durable numeric allowance for automated free-model dictation is **unconfirmed**. [Kimi limits](https://www.kimi.com/code/docs/en/kimi-code/membership.html), [Zen pricing](https://opencode.ai/docs/zen/)

### Rating: unclear

The local executable supports automation, but there is no blanket subscription authorization. Each provider/authentication route needs its own rating; Claude and Kimi subscription routes are unsuitable without clarification or permission. [Provider docs](https://opencode.ai/docs/providers/), [Kimi guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html)

### Rule summary

Google now explicitly documents `agy -p`, capturing stdout in scripts, cached official authentication, and CI execution. Consequently, “Google prohibits all Antigravity automation” is not supported by the current documentation. [Headless docs](https://antigravity.google/docs/cli/headless/)

However, Additional Terms §6 prohibit third-party software accessing the service and include using it with products Google does not provide. The FAQ repeats the restriction. Whether a local program spawning official `agy`, without handling tokens or contacting the backend, is exempt is **unconfirmed**. [Additional Terms](https://antigravity.google/terms), [FAQ](https://www.antigravity.google/docs/faq/)

**Confirmed enforcement:** Google’s February 27 announcement attributes bans to third-party tools/proxies accessing Antigravity resources and quotas. It confirms collateral blocks on Gemini CLI and Gemini Code Assist, describes reinstatement, and warns that a second violation brings a permanent ban. It does **not** establish that ordinary official `agy -p` use caused those bans, or that Gmail/Drive were deleted. Those broader claims are **unconfirmed**. [Google announcement](https://github.com/google-gemini/gemini-cli/discussions/20632)

### Quota/rate limits

Non-Pro/Ultra users have quota refreshing weekly. Google AI Pro has five-hour refreshes until its weekly limit is reached; Ultra has higher five-hour and weekly allowances. Limits depend on agent work and available capacity, rather than a guaranteed prompt count. Pro/Ultra can enable purchased-credit overages. No fixed allowance for Pumice was confirmed. [Plans](https://antigravity.google/docs/plans)

### Rating: risky

Official scripting support reduces uncertainty about the command itself. The broad wrapper restriction and demonstrated enforcement justify keeping Pumice’s adapter disabled pending clarification. No Antigravity command was executed. [Terms](https://antigravity.google/terms), [Enforcement announcement](https://github.com/google-gemini/gemini-cli/discussions/20632)

## Findings

- **Anthropic’s June headless quota split is paused.** The official notice says subscription limits still cover `claude -p` and SDK use; the preserved credit table is not active policy. [Pause notice](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
- **Official CLI use is insufficient by itself to establish permission for a product integration.** Anthropic distinguishes ordinary native use from third-party products using subscription credentials. [Legal docs](https://code.claude.com/docs/en/legal-and-compliance)
- **Codex explicitly supports scripted execution and documents account-authenticated automation.** This supplies the strongest evidence for Pumice’s personal subscription workflow. [Non-interactive docs](https://learn.chatgpt.com/docs/non-interactive-mode)
- **Kimi prohibits non-interactive subscription automation despite providing `-p`.** Its OpenCode support is client compatibility, not an automation exemption. [Guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html), [Command docs](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-command)
- **OpenCode’s software license does not grant upstream subscription rights.** Its documentation explicitly identifies Claude subscription access as prohibited. [License](https://github.com/anomalyco/opencode/blob/dev/LICENSE), [Provider docs](https://opencode.ai/docs/providers/)
- **Antigravity has documented headless support and confirmed third-party-access bans.** These are separate facts; bans for normal official headless use remain **unconfirmed**. [Headless docs](https://antigravity.google/docs/cli/headless/), [Google announcement](https://github.com/google-gemini/gemini-cli/discussions/20632)

3. **Defer subscription-backed Kimi support or obtain an explicit exception?** The spec lists:

   > “S2.4 Kimi via the Kimi CLI, according to the outcome of S0.2.”

   Technical viability alone is insufficient: current subscription guidelines prohibit the intended non-interactive use. [Spec](../spec.md), [Kimi guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html)

   OpenCode is its own official tool but a third-party client to model providers. Kimi approves that client but restricts automation; Claude subscription access is prohibited. Hosted Zen also needs clarification of its output-extraction clause before being treated as an approved alternative. [Spec](../spec.md), [OpenCode provider docs](https://opencode.ai/docs/providers/), [Hosted Terms](https://opencode.ai/legal/terms-of-service)

5. **Refine the Antigravity risk wording while retaining the disabled default?** The spec describes:

   > “Antigravity: unstable non-interactive mode and reports of accounts banned for automation”

   Current primary sources document headless mode and identify third-party tools/proxies as the cause of the confirmed ban wave. Wrapper permission and bans caused solely by official headless use remain **unconfirmed**. Obtain Google clarification before enabling Pumice’s adapter. [Spec](../spec.md), [Headless docs](https://antigravity.google/docs/cli/headless/), [Ban announcement](https://github.com/google-gemini/gemini-cli/discussions/20632)
