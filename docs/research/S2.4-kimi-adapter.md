# S2.4 — Kimi Code CLI adapter

## Findings

**CLI:** Kimi Code CLI `2.1.1` (`kimi --version`), single-binary install at `~/.kimi-code/bin/kimi`, logged in (owner account, region global). Model aliases verified with `kimi provider list --json`: `kimi-k2`, `kimi-k2-thinking`, `kimi-k2.5`, `kimi-k2.6`, `kimi-k2.7-code`, `kimi-k2.7-code-highspeed`, `kimi-k2.8`, `kimi-k2.8-code`, `kimi-k3`, `kimi-k3-256k`. The account default is `kimi-k2.8-code`; the adapter default is `kimi-k2.7-code-highspeed` (the cheapest alias that works, per the orchestrator's instruction).

This note supersedes the standby verdict of [`S2.4-kimi-integration.md`](S2.4-kimi-integration.md) for transport: that investigation concluded "no stdin transport" and stopped. This story re-examined the bundled 2.1.1 source and confirmed print mode is the only viable channel, then implemented the adapter with the argv transport and a size guard.

### Invocation (verified with real calls)

```sh
env -u KIMI_CODE_TRUST_WORKSPACE \
  KIMI_CODE_BACKGROUND_PRINT_BACKGROUND_MODE=exit \
  KIMI_CODE_BUILTIN_PRODUCT_SKILLS=false \
  KIMI_DISABLE_TELEMETRY=1 \
  KIMI_CODE_NO_AUTO_UPDATE=1 \
kimi \
  --agent-file <abs path>/pumice-agent.md \
  --skills-dir . \
  --output-format stream-json \
  --model kimi-k2.7-code-highspeed \
  -p "<user message>"
```

- **Transport:** print mode passes the `-p` value as the user message text. There is no stdin sentinel and no prompt-file option: upstream `run-v2-print.ts` (commit `1f6f0b1`) submits `opts.prompt` verbatim, and `-p -` supplies a literal dash (verified). ACP (`kimi acp`) speaks JSON-RPC on stdin but its command registration forwards no agent-file/model/tools flags and withholding fs/terminal capabilities falls back to local operations, so it cannot meet the no-tools rule. The dictation therefore travels as **one argv element**, capped at 24 KiB (`InputTooLarge` beyond that; argv limits are 128 KiB per argument on Linux and a 32 KiB total command line on Windows). Stdin is closed unused.
- **System prompt:** a custom agent file (`--agent-file`), the documented highest-priority launch intent. Front matter `tools: []` (disables every tool, including MCP globs) and `subagents: []` (no delegation); the Markdown body is the composed system prompt. The body is rendered as a `${var}` template: unknown variables stay verbatim, but the documented context variables (`${cwd}`, `${now}`, `${base_prompt}`, …) in *configured* instructions would expand — Pumice's own prompt carries none.
- **Restriction flags:** print mode auto-approves tools by default and rejects `--yolo`/`--auto`/`--plan` together with `--prompt`, so the empty agent allowlist is the load-bearing restriction; any `tool_calls`/`tool` record in the stream is rejected as `UnexpectedToolActivity`. `--skills-dir .` (the empty workspace) replaces user/project skill directories; `KIMI_CODE_BUILTIN_PRODUCT_SKILLS=false` turns off built-in product skills (2.1.1 `builtinProductSkills` config section). `KIMI_CODE_BACKGROUND_PRINT_BACKGROUND_MODE=exit` returns right after the main turn (the built-in default `steer` waits for background tasks). `KIMI_DISABLE_TELEMETRY=1` keeps runs off the telemetry intake (`shouldEnableTelemetry`, env kill-switch `KIMI_DISABLE_TELEMETRY`). `KIMI_CODE_NO_AUTO_UPDATE=1` blocks update checks. `KIMI_CODE_TRUST_WORKSPACE` is removed from the child so an inherited value cannot mark the fresh workspace trusted (trust is what keeps configured MCP servers from starting in it). One bug was caught by the real end-to-end run: the generated agent file originally missed the closing `---` front-matter fence, which the CLI rejects ("Missing closing frontmatter fence", exit 1); the contract tests only asserted field presence, and now assert the closed fence.
- **Residual unverifiables:** user-configured hooks (`onBeforeSubmitPrompt` etc.) and plugin MCP servers have no per-launch off switch — agent tool removal does not stop hook scripts or MCP server startup; print mode persists a resumable session under the user's own `~/.kimi-code` (a resume hint with the session id is printed on stdout; the parser ignores it).
- **Output:** `--output-format stream-json` prints one JSON message per line, verified by real capture:

  ```json
  {"role":"meta","type":"system.version","version":"2.1.1"}
  {"role":"assistant","content":"…"}
  {"role":"meta","type":"session.resume_hint","session_id":"…","command":"kimi -r …","content":"…"}
  ```

  Tool activity appears as an assistant message with `tool_calls` followed by `{"role":"tool","tool_call_id":"…","content":"…"}`. Failures retry as `{"role":"meta","type":"turn.step.retrying",…,"error_name":"…","error_message":"…","status_code":401}` — the adapter classifies from `status_code` (401 → not logged in, 403 → auth rejected, 429 → rate limited) and `error_name`/`error_message` containing "quota" (quota), never copying message text. A hard turn failure exits nonzero with the reason on stderr; without structured evidence that maps to a plain nonzero-exit failure.

### Enablement

Registered like the other providers; **off by default** (`disabled_by_default`) with a fixed risk warning citing the S0.3 "risky" terms rating (Moonshot subscription guidelines restrict non-interactive automation). Enabling requires nothing but `enabled: true` (default model `kimi-k2.7-code-highspeed`; any `kimi provider list` alias works). No adapter options and no environment overrides are accepted. Doctor's static standby note and the `--login-check` refusal are removed; `pumice doctor` and `--login-check --provider kimi` work like the other providers. The shared contract suite passes for kimi except the generic 200 KiB transport case, which the argv transport rejects by design — a kimi-specific transport case asserts byte-exact `-p` payload, empty stdin, the control-file placement, and the `InputTooLarge` guard instead.

## Questions for the owner

1. **Subscription terms** (carried from S0.3/S2.4): the adapter automates subscription-backed calls despite the community guidelines' "don't use Kimi Code for non-interactive automation" line. Enabling kimi is your call; the risk warning says as much. Resolve with Moonshot if unattended dictation should run on this subscription.
2. **Default model**: `kimi-k2.7-code-highspeed` is the cheapest alias verified in your account. If a cheaper/newer alias appears (or you prefer `kimi-k2.8-code`'s quality), change `providers.kimi.model`.
3. **Session retention**: print mode writes a resumable session (including the dictation) under `~/.kimi-code/sessions` with no suppression flag. Claude/Codex equivalents keep CLI-owned transcripts too, but confirm this matches your privacy expectation.
4. **Hooks/plugins**: if your `config.toml` ever defines hooks or enables plugins, they can run on print-mode events regardless of the agent's empty tool list. Review before enabling; there is no per-launch off switch to enforce from the adapter.

No credential files were read or copied; `config.toml` was inspected for non-secret key names only. No global configuration was changed. Four real inference calls were made (within the 10-call budget), each in a fresh empty directory.
