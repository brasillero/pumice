# S2.4 — Kimi integration investigation

## Findings

The owner requested integrating the official Kimi CLI before CLI-managed model configuration. The provider registry supports new modules through ProviderDescriptor/CliAdapter and the shared ProcessRunner/adapter contract; the registry itself is not the blocker. No adapter or real dictation call was implemented during this investigation.

Installed Kimi Code CLI help identifies the relevant 2.1.1 interface. Source inspection uses official upstream commit `21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3`; source findings are not a live inference conformance test of the installed binary.

Print mode passes its prompt argument directly as user text. No stdin sentinel or prompt-file expansion was found: `-p -` supplies a literal dash. This conflicts with Pumice's existing shared tests, which keep dictated text out of argv and exercise 200 KiB input across platforms. The no-tools Markdown agent profile works for this mode, but does not solve transport. Putting transcript text inside the agent body would change system/user separation. [Print runner](https://github.com/MoonshotAI/kimi-code/blob/21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3/apps/kimi-code/src/cli/v2/run-v2-print.ts#L304), [submission](https://github.com/MoonshotAI/kimi-code/blob/21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3/apps/kimi-code/src/cli/v2/run-v2-print.ts#L565), [agent profiles](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/agents.html).

ACP supports stdin JSON-RPC, but its command registration does not forward the global agent-file/model/skills flags. Session creation has no corresponding per-session tools or system-prompt override; its configuration controls model, thinking and mode. Withholding filesystem/terminal client capabilities falls back to local operations rather than disabling them. [Registration](https://github.com/MoonshotAI/kimi-code/blob/21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3/apps/kimi-code/src/cli/sub/acp.ts), [session creation](https://github.com/MoonshotAI/kimi-code/blob/21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3/packages/acp-server/src/server.ts#L242), [filesystem fallback](https://github.com/MoonshotAI/kimi-code/blob/21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3/packages/acp-server/src/acp-fs/acpFsService.ts#L68), [terminal fallback](https://github.com/MoonshotAI/kimi-code/blob/21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3/packages/acp-server/src/acp-terminal/acpTerminalRunner.ts#L58).

No independent per-launch tools-policy configuration overlay was found. Moving KIMI_CODE_HOME also moves configuration, credentials and session storage; copying credentials or rewriting the user's configuration is not an acceptable adapter solution. [Bootstrap configuration resolution](https://github.com/MoonshotAI/kimi-code/blob/21406fb4c805cc8c715e6d1f16ad3fb5f25f4fe3/packages/agent-core-v2/src/app/bootstrap/bootstrap.ts#L168).

Separately, the current subscription guidelines still restrict non-interactive automation. The supervised coding-worker role previously approved by the owner is distinct from subscription-backed unattended dictation processing. [Guidelines](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html).

The recommended small-scope path is to leave Kimi on standby and work on CLI-managed configuration for existing providers. Kimi can be reconsidered if upstream print mode supports stdin or ACP can honor per-launch no-tools agent profiles. A generic ACP client alone does not resolve the restriction gap.
