# S2.9 — Kiro adapter (`kiro-cli`)

Owner request (2026-10-06): add a Pumice provider adapter for the AWS Kiro CLI,
provider id `kiro`.

## Findings

### Installed CLI version

```text
$ kiro-cli --version
kiro-cli 2.24.1
```

The owner stated the CLI is installed but **not set up for use** (no login, no
API key). Only `--version`, `--help` and `<subcommand> --help` style commands
were run locally. No `kiro-cli chat` prompt was sent.

### Invocation chosen

```text
kiro-cli chat --v3 --no-interactive --agent pumice --model <model> \
    --output-format stream-json --trust-tools=
```

* `--v3` selects the V3 agent engine, required for `--output-format stream-json`
  ([Headless mode docs](https://kiro.dev/docs/cli/headless/)).
* `--no-interactive` runs headlessly without prompting.
* `--agent pumice` selects a custom agent. The help text only documents the
  agent name (`--agent <AGENT>  Context profile to use`); it does not show a
  file-path form. `kiro-cli agent --help` states that **"local agents are only
  discovered if the command is invoked at a directory that contains them"**, so
  the adapter places the custom agent at `.kiro/agents/pumice.json` inside the
  call's working directory and lets Kiro discover it by name.
* `--model <model>` pins the model; an explicit model is required when the
  provider is enabled.
* `--output-format stream-json` emits ACP v2 events as JSON Lines on stdout
  ([Headless mode docs](https://kiro.dev/docs/cli/headless/)).
* `--trust-tools=` (empty value) trusts no tools; the help text explicitly
  documents this as the way to "trust no tools".
* No `--trust-all-tools`.
* The instruction travels as stdin (no positional argument), matching the
  headless docs: "When stdin is piped and no positional argument is given, Kiro
  reads the full stream as the instruction."

### System prompt / agent configuration

Kiro has no `--system-prompt` CLI flag. The documented way to provide
instructions to a headless run is a custom agent file
([Custom agents docs](https://kiro.dev/docs/custom-agents/)).

The adapter creates a workspace-local agent at `.kiro/agents/pumice.json`
containing:

* `name`: `pumice`.
* `prompt`: the system prompt.
* `tools: []`: exposes no tools.
* `excludedTools: ["knowledge"]`: excludes the knowledge tool.
* `includeMcpJson: false` and `includePowers: false`: disables inclusion of
  MCP JSON and Powers configurations from the agent file.
* `mcpServers: {}` and `hooks: {}`: per-agent empty maps so the user's global
  MCP servers and hooks do not enter the call.

This is a deliberate, small deviation from the "fresh, empty temporary
directory" rule: the adapter must place one local agent file where Kiro can find
it, because the CLI has no documented `--system-prompt` or file-path `--agent`
flag. The user's real `~/.kiro` profile is left untouched.

### `KIRO_HOME` override removed

The first implementation set `KIRO_HOME=../control` so the adapter could supply
`agents/pumice.json` and `settings/cli.json` without touching the user's real
profile. Review feedback (Round 2, 2026-10-06) noted that `KIRO_HOME` relocates
"global agents, prompts, skills, steering, settings, and sessions" per the Kiro
docs, which would hide the user's own `~/.kiro/settings/cli.json` (gateway,
model defaults, local config). Following the same owner decision that fixed
Claude (`--restricted`) and Codex (`--ignore-user-config`), the adapter now:

* does **not** set `KIRO_HOME`;
* does **not** create a `settings/cli.json` override;
* supplies the workspace-local agent file described above.

The user's own Kiro login, settings and global agents remain active.

### Tool lockdown

* `tools: []` in the agent file should make no tools available.
* `--trust-tools=` (empty) is documented to trust no tools.
* No `--trust-all-tools`.
* Any `tool_call_update` or `tool_call_content_chunk` event observed in the
  output stream is rejected as `UnexpectedToolActivity`.

**Unverified (documentation only):** whether `tools: []` truly disables *all*
built-in V3 tools, including knowledge/code intelligence, or whether the
additional `excludedTools` / `includeMcpJson` / `includePowers` / `mcpServers` /
`hooks` fields are necessary or even recognized by `kiro-cli 2.24.1`. The
adapter applies them as defense in depth, but they were not runtime-tested.
There is no documented CLI flag to disable MCP servers or hooks for a single
call; the agent-level fields are the only per-call knobs found.

### Output format and parsing

`--output-format stream-json` emits ACP v2 `session/update` events as JSON
Lines. The parser accepts either the raw `params.update` object or the full
JSON-RPC `session/update` notification wrapper.

Relevant ACP v2 docs:
[Prompt Lifecycle](https://agentclientprotocol.com/protocol/v2/prompt-lifecycle).

The parser collects text from:

* `sessionUpdate: agent_message` — full message upsert.
* `sessionUpdate: agent_message_chunk` — streamed text chunk.

It rejects any `tool_call_update` / `tool_call_content_chunk` and waits for a
final `state_update` with `state: idle` and `stopReason: end_turn`.

**Unverified (documentation only):** the exact envelope shape produced by
`kiro-cli` (raw `params.update` vs wrapped JSON-RPC notification), the exact
stop-reason values used on success, and whether the CLI emits
`agent_message_chunk` or only full `agent_message` events. The parser handles
both and treats any non-`end_turn` idle stop reason as a failure.

### Error classification

* Missing authentication: the ACP v2 docs show a `state_update` with
  `stopReason: error` and `error.code: -32000` ("Authentication required"). The
  parser classifies this as `NotLoggedIn`.
* Rate limit / quota: no documented structured signature was found in the ACP
  docs or Kiro headless docs. The adapter does not currently classify these
  separately; they will surface as `NonzeroExit` or `InvalidOutput` until a
  documented signature is verified.

**Unverified (documentation only):** the exact stderr / stdout signature for a
not-logged-in Kiro run, and whether Kiro emits a JSON-RPC error response, an
ACP `state_update` error, or plain stderr text.

### Detection / doctor

Detection runs `kiro-cli --version`. The install hint points to the official
installer documented at
[Installation](https://kiro.dev/docs/getting-started/installation/):
`curl -fsSL https://cli.kiro.dev/install | bash`.

### Latency

No real call was made; latency is unmeasured.

## Implementation notes

* The adapter ships **disabled by default** with a `risk_warning`.
* `enabled: true` requires an explicit `model`; no adapter-specific `options` or
  `env` overrides are allowed.
* The shared `ProcessRunner` gained a `workspace_files` channel so the adapter
  can write `.kiro/agents/pumice.json` inside the CLI's working directory
  without relocating the user's global profile. The directory is otherwise
  empty.
* The fake CLI was extended with a `report_files` scenario key so the contract
  suite can inspect the generated agent file.
