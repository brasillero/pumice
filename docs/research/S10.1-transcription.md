# S10.1 — Transcription engine (`transcribe-cpp`)

Owner direction (2026-10-12): add a speech-to-text layer, CPU only for now,
behind an OpenAI-compatible `POST /v1/audio/transcriptions` (task notes:
`.task-decisions/tasks/s10.1-transcription/`). This note records the engine
spike. The spike code lives outside the repository (`~/scratch/stt-spike` on
server-1); nothing here is in Pumice yet.

## Candidate

[`transcribe-cpp`](https://crates.io/crates/transcribe-cpp) 0.3.1 (MIT), Rust
bindings to [handy-computer/transcribe.cpp](https://github.com/handy-computer/transcribe.cpp),
a ggml-based C/C++ speech-to-text library from Handy's team. Handy uses this
crate for its Whisper models (`src-tauri/Cargo.toml`, declared with
`default-features = false`). It reads the same GGUF files Handy downloads, so
Pumice can use the model a Handy user already has.

## Test setup

- Machine: server-1, Linux x86-64, Intel i5-14500T (20 threads), 30 GB RAM.
- Toolchain: rustc/cargo 1.99.0, GCC/G++ 15.2.0, GNU Make 4.4.1, CMake 4.4.4
  (user-local install from the official release, sha256 checked).
- Audio: the owner's 14.19 s sample, WAV 16 kHz mono 16-bit, Brazilian Portuguese.
- Models, from Handy's catalog at the revisions Handy pins, sha256 checked:
  - `whisper-large-v3-turbo-Q8_0.gguf` (886 MB), the owner's Handy model,
    from `handy-computer/whisper-large-v3-turbo-gguf` @ `5eaf945c`;
  - `whisper-tiny-Q8_0.gguf` (46 MB), from `handy-computer/whisper-tiny-gguf` @ `6687f30c`.
- Crate: `transcribe-cpp = { version = "=0.3.1", default-features = false, features = ["serde"] }`.

## API

```rust
use transcribe_cpp::{Backend, Model, ModelOptions, RunOptions, SessionOptions};

let model = Model::load_with(model_path, &ModelOptions {
    backend: Backend::Cpu, ..Default::default()
})?;
let mut session = model.session_with(&SessionOptions {
    n_threads: 20, ..Default::default()
})?;
let result = session.run(&pcm, &RunOptions::default())?; // result.text, result.language
```

- Input is mono 16 kHz `f32` PCM in [-1, 1]. The engine does not decode or
  resample audio; Pumice must turn the uploaded file into that.
- `RunOptions::default()` transcribes with language auto-detection.
- A `Model` is `Send + Sync`; a session is `Send`, not `Sync`. Sessions of one
  model serialize on the model's mutex, so parallel transcriptions need
  separate loaded models (about 1 GB each for turbo Q8_0).

## Build

- Needs CMake 3.16+ and a C/C++17 compiler besides Rust. The C/C++ source is
  bundled in `transcribe-cpp-sys`; nothing is downloaded at build time.
  Bindings are pregenerated (no clang/libclang).
- Features: the default `metal` is turned off by `default-features = false`.
  Leave out `shared`, `dynamic-backends`, `openmp` and the GPU features: they
  add runtime libraries. `dynamic-backends` is what Handy's Windows x64 build
  uses for per-CPU modules, which is why Handy ships extra DLLs.
- CMake flags go through `TRANSCRIBE_CMAKE_ARGS`. Pass
  `-DTRANSCRIBE_USE_SYSTEM_BLAS=OFF` so a BLAS found on the build host is not
  linked.
- The native code links into the executable as static archives: no ggml or
  transcribe shared library is needed at runtime.

## Static Linux build (musl)

Pumice's Linux release is a fully static `x86_64-unknown-linux-musl`
executable. The glibc spike links the system `libstdc++`, `libgcc_s`, `libm`
and `libc` dynamically, so the musl build was checked separately. It works:
`file` reports `static-pie linked`, `ldd` reports `statically linked`, and the
binary transcribes the sample with the same turbo text (5.3 MB with AVX2).

What it needs, compared with today's release workflow:

- **A musl C++ compiler.** Ubuntu's `musl-tools` has only a C wrapper. The spike
  used the prebuilt [cross-tools/musl-cross](https://github.com/cross-tools/musl-cross/releases/tag/20261001)
  `20261001` toolchain (GCC/G++ 16.2.0, musl 1.2.6), downloaded with its
  published sha256 checked; no root needed, so it can run on `ubuntu-latest`
  (not tried there yet).
- **A linker wrapper.** The musl GCC must link `libstdc++.a` and then rescan
  static `libc` and `libunwind`; the wrapper replaces `-lstdc++` with the path
  of `libstdc++.a` and appends `-Wl,-Bstatic -lc -lunwind`. Rust flags:
  `-C target-feature=+crt-static -C link-self-contained=yes`.
- **Explicit CPU flags.** When cross-compiling, ggml turns SIMD off by default,
  so an AVX2 build passes them explicitly:
  `-DGGML_NATIVE=OFF -DTRANSCRIBE_USE_SYSTEM_BLAS=OFF -DGGML_SSE42=ON -DGGML_AVX=ON -DGGML_AVX2=ON -DGGML_F16C=ON -DGGML_FMA=ON -DGGML_BMI2=ON`
  through `TRANSCRIBE_CMAKE_ARGS`.

Speed: turbo took 7.7, 8.4 and 8.4 s with AVX2 (mean 8.2 s) against 8.3 s for a
glibc AVX2 rerun made at the same time, so no musl penalty showed up; the
earlier 7.1 s glibc mean was measured on a quieter machine. The plain x86-64
musl build took 20.0 s. An independent rerun of the static AVX2 binary gave
7.6 s and the same text.

## All release targets (CI)

The `stt-spike` workflow (`.github/workflows/stt-spike.yml`, spike crate in
`spikes/stt/`) builds the spike for each release target, checks its runtime
dependencies, and transcribes the sample with Whisper Tiny Q8_0 (sha256 pinned).
All four passed on PR #91 (run 38212835534):

| Target | Runner | Binary | Runtime dependencies | Tiny transcription |
| --- | --- | --- | --- | --- |
| `x86_64-unknown-linux-musl` | ubuntu-latest | 5.3 MB | none (static-pie) | 0.66 s, `pt` |
| `x86_64-pc-windows-msvc` | windows-latest | 3.7 MB | `KERNEL32`, `ADVAPI32`, `ntdll`, `api-ms-win-core-synch-l1-2-0` | 0.70 s, `pt` |
| `x86_64-apple-darwin` | macos-15-intel | 4.0 MB | system libraries only | 0.53 s, `pt` |
| `aarch64-apple-darwin` | macos-15 | 3.4 MB | system libraries only | 1.14 s, `pt` |

Runners have 3 or 4 threads, so times are not comparable with server-1.

Windows needed one fix: the `cmake` crate does not pass Rust's `+crt-static`
on to CMake, so the C/C++ objects were built for the DLL runtime (`/MD`) and
failed to link (`__imp_*` unresolved). Passing
`-DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` in `TRANSCRIBE_CMAKE_ARGS` fixes
it; both CMake projects in the crate (`cmake_minimum_required` 3.16 and
3.14...3.28) honour that variable. `api-ms-win-core-synch-l1-2-0.dll` is a
Windows API set (part of the OS since Windows 8) imported by Rust's standard
library; no C runtime DLL is imported.

The Windows job log shows the transcript with broken accents (`Ent�o`). The
check (language `pt`, non-empty text) passed; the broken characters are most
likely the log's encoding of the smoke script's output, not the transcript
itself. To confirm when the endpoint returns JSON.
