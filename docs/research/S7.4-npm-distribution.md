# S7.4 — npm-compatible CLI distribution

Research note for story S7.4 (npm distribution). Findings from official
sources, checked 2026-10-05.

## Findings

### Approved channel (owner decision, 2026-10-05)

The owner approved distributing Pumice through **GitHub release binaries plus
an npm package** installable with npm, pnpm, Bun and npx. This approved
package channel **replaces the spec's Tauri-based installer/auto-update
plan**, which stays deferred (along with autostart). Bare service startup and the
installation guide are handled in S7.3. No Tauri, GUI, updater or autostart work is
in this story.

### Package layout

- **Front package `pumice`** (owner-requested short name; registry 404 on
  2026-10-05, not reserved until publication): a zero-dependency CommonJS
  launcher (`bin/pumice.js`, shebang `env node`, Node >= 22 per `engines`),
  LICENSE and README. `optionalDependencies` pin the four native packages at
  the exact version read from `Cargo.toml`, so the front and its native
  payload can never drift apart.
- **Native packages `@brasillero/pumice-{linux-x64,win32-x64,darwin-x64,darwin-arm64}`**:
  each contains exactly one executable, LICENSE and `package.json` with `os`/
  `cpu` selectors. Package managers skip non-matching optional dependencies,
  so only one native binary is installed. The static Linux musl binary runs
  on both glibc and musl systems, so a single `linux-x64` package covers
  Linux. Ownership of the `@brasillero` scope must be verified before
  publishing.
- Manifests link the real repository page via `repository`/`homepage`/`bugs`.

### Launcher behavior (scripts/npm/bin/pumice.js)

Validates the platform against the front manifest's optionalDependencies,
resolves the native package with `require.resolve(name + '/package.json',
{paths: [__dirname]})` (works under pnpm's isolated layout; **the caller's
cwd is deliberately not a fallback** — a planted `node_modules` in a random
directory must not satisfy the dependency), checks the versions match, checks
the binary exists, then spawns it with inherited stdio/cwd/env — no shell.
Exit codes propagate; SIGINT/SIGTERM are forwarded and the launcher re-raises
the signal when the child exits by a signal. Error messages cover unsupported platform, missing native
package, version mismatch, missing binary and spawn errors. The launcher
never downloads anything and runs no install scripts.

### Staging and verification (scripts/package_npm.py)

Development-only, stdlib-only. Before staging anything it verifies the input
directory holds **exactly the four release archives** from S7.1 plus their
`SHA256SUMS`, with strict parsing (malformed or duplicate checksum lines are
rejected). Only the single expected regular binary member is extracted from
each archive — symlinks, hard links, directories and traversal names are
rejected, and there is no blind `extractall`. Native bytes are identical to
the release archive and keep mode 0755. Each of the five staged folders is
packed with `npm pack --ignore-scripts` (portable resolution prefers
`node + npm-cli.js` over `.cmd`/`.bat` shims on Windows; no shell strings),
and SHA-256 checksums of the tarballs are emitted. Nothing is published.

### Loopback test registry (scripts/npm_registry_fixture.py)

A stdlib-only HTTP server on 127.0.0.1 that derives packuments from the
generated tarballs, so npm/pnpm/Bun installs can be tested against the exact
tarballs that would be published by pointing `--registry` at the fixture —
exercising the real resolution path (optional-dependency platform skipping,
exact version pins) without publishing. Bind is loopback-only; there is no
host/public bind option.

### Tests

- `scripts/test_npm_launcher.py`: argv (spaces/metacharacters), stdin/out/err,
  exit codes, SIGTERM propagation, and every failure message; plus a
  regression test that a fake native package in the caller's cwd cannot
  rescue a missing dependency. Fake binary only, no AI calls.
- `scripts/test_npm_install.py`: five fake tarballs served through the
  fixture; npm/pnpm/Bun local installs, isolated npm global-prefix install
  and npx. The suite isolates each manager with explicit per-tool
  config/cache locations (empty npm userconfig/globalconfig, npm_config_cache,
  XDG_*, PNPM_HOME, project-local bunfig cache) and **never overrides
  HOME/USERPROFILE**. The fake native binary is a POSIX shell script, so
  execution assertions skip on Windows (the CI smoke job covers Windows with
  the real binary).
- `scripts/test_package_npm.py`: staging/packing against a fake npm, plus
  every failure mode (missing/extra archives, malformed/duplicate/mismatched
  checksums, symlink members).

### CI (.github/workflows/release.yml)

After the S7.1 `checksums` job, an `npm-pack` job downloads the real release
preview (four archives + SHA256SUMS), stages and packs the five tarballs and
uploads them as an `npm-preview` artifact. Then:

- `npm-smoke` runs on all four hosts (linux-x64, win32-x64, darwin-x64,
  darwin-arm64): start the fixture, `npm install -g pumice@<version>
  --registry <fixture>` into an isolated prefix with empty user/global
  configs, and assert `pumice --version` prints `pumice <version>`.
- `npm-smoke-managers` runs on Linux with pnpm (pnpm/action-setup@v6, 12.6)
  and Bun (oven-sh/setup-bun@v2, 1.4.2): `pnpm add -g` / `bun add -g`
  through the fixture, same version assertion.

All jobs run with `permissions: contents: read`, no secrets, no publishing.

### Manual publishing checklist (for the owner, nothing automated)

1. Verify ownership of the `@brasillero` npm scope and the `pumice` package
   name (unregistered as of 2026-10-05).
2. Publish the **four native packages first**, then the front package with
   `--access public`, all at the same exact version.
3. Attach the four release archives + `SHA256SUMS` to the GitHub release.

### Reviewed validation

All four S7.1 archive builds and extracted-binary smoke checks passed in
[PR #36](https://github.com/brasillero/pumice/pull/36). The root reviewer used
those real archives to produce the five npm tarballs, then verified isolated
npm, pnpm and Bun global installs plus npx on Linux (`pumice 0.1.0`).
The 33 packaging tests passed with all three managers enabled. Native npm
installation on Windows and macOS awaits this story's CI.
